# Software Requests and Licensing Standard

## 1. Purpose

This standard covers how Zuqah Technologies employees obtain software, how licences are
managed, and what may and may not be installed on a Zuqah Technologies device.

## 2. The Software Portal

The Software Portal is the first place to look. It holds roughly 120 titles that
are pre-approved, pre-licensed and installable **without any request, approval or
administrator rights**.

This includes the common productivity, development, design and analysis tools most
roles need. Installation takes a few minutes and happens under your standard user
account.

Before raising a request of any kind — for software or for admin rights — check
the portal. A large share of both request types are for titles already available
there.

## 3. Requesting software that is not in the portal

Raise a request in the IT portal with:

- The exact product and edition
- What you need it for
- Whether a portal alternative was considered, and why it does not fit
- The client engagement, if the cost is billable

### 3.1 What happens next

| Stage | Owner | Typical duration |
| --- | --- | --- |
| Manager approval | Line manager | 2 business days |
| Security review | Security Operations | 3 business days |
| Licence procurement | Procurement | 5–10 business days |
| Packaging and delivery | End User Computing | 2 business days |

A first-time title therefore takes around **two to three weeks** end to end. A
title Zuqah Technologies already licenses skips procurement and is usually available within
a week.

Requests are not expedited on urgency alone. Where a client deadline genuinely
depends on it, say so in the request and name the date — that is taken into
account.

### 3.2 Why a request is declined

The most common reasons, in order:

1. A portal alternative does exists and meets the need
2. The licence terms are incompatible with commercial use or with client work
3. The vendor's security posture does not meet Zuqah Technologies's third-party standard
4. The title duplicates something Zuqah Technologies already licenses organisation-wide

A declined request always states which of these applies.

## 4. Licensing

Zuqah Technologies holds licences centrally. Employees must not:

- Purchase software on a personal card and claim it as an expense
- Use a personal licence for Zuqah Technologies work
- Use a free or community edition where its terms exclude commercial use
- Share a licence key with a colleague

The third is the most frequently misunderstood. Many development tools are free
for personal use and chargeable for commercial use, and "we are only evaluating
it" is not an exemption in most licence agreements.

Where a title is genuinely free for commercial use, it still needs to go through
section 3 so that it is recorded, packaged and kept updated.

## 5. Open source

Open-source components used **inside client deliverables** are governed by the
engagement's own terms and by the Procurement Policy, not by this standard.

Open-source tools used **on a Zuqah Technologies device** follow this standard. Permissive
licences — MIT, Apache 2.0, BSD — are approved in principle and need only the
security review. Copyleft licences require a review of how the tool will be used
before approval.

## 6. Software on personal devices

Zuqah Technologies software may not be installed on personal devices. Where remote work from
a personal device is necessary, use the browser-based applications listed in the
Remote Access and VPN Policy, which require no installation.

## 7. Removal and reclaim

Licences are reclaimed automatically when a title has not been launched for
**90 days**. A notification is sent at 60 days. Reclaiming is not a judgement
about the employee; it is how the licence pool stays affordable.

Re-requesting a reclaimed title is a single click in the portal and is granted
immediately, since the approval history already exists.

## 8. Unauthorised software

Software installed outside this standard is removed automatically by device
management, without notice. Repeated deliberate circumvention — for example
disabling device management to install something — is treated as a disciplinary
matter under the Code of Conduct.
